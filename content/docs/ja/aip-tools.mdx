<h2 id="choose">ツールの種類を選択</h2>

| 設定 | 用途 |
| --- | --- |
| HTTP 動的ツール | 名前、入力、結果が明確な業務操作を提供 |
| イベントツール | 既存の連携先にツールイベントを送り、応答テンプレートを設定 |
| HTTP プロキシ | 許可するホストと追加するリクエストヘッダーを設定 |

<h2 id="http">HTTP 動的ツールを設定</h2>

注文照会の例では、リクエストを受けて JSON を返す業務 API を準備します。

1. Agent 編集画面で業務ツールを開き、HTTP ツールを追加します。
2. 名前を `lookup_order`、説明を「注文番号から現在の状態を照会」にします。
3. 業務サービスの URL を入力します。
4. 必須の文字列 `order_id` を入力スキーマに定義します。
5. 認証が必要ならヘッダーでバインド済みシークレットを参照します。
6. ツール設定を適用し、Agent を保存します。

```json
{
  "type": "object",
  "properties": {
    "order_id": {"type": "string", "description": "顧客が提示した注文番号"}
  },
  "required": ["order_id"],
  "additionalProperties": false
}
```

デバッグで「注文 DEMO-001 の状態を調べて」と送ります。番号はテストデータに置き換えてください。ツール、引数、回答に必要な結果が正しいか確認します。

<h2 id="proxy">HTTP プロキシを設定</h2>

業務要件に合わせてホストルールとヘッダーを設定します。プロンプトに実際のトークンを貼らず、シークレットを参照してください。別の送信先に認証ヘッダーが渡らないよう、保存前にホスト範囲を確認します。

<h2 id="troubleshoot">呼び出しに失敗した場合</h2>

デバッグのツールエラーを確認し、URL、入力スキーマ、ヘッダー、シークレットのバインドを点検します。ツール画面の適用は下書きだけを更新するため、その後 Agent を保存します。

イベントツールには対応する業務イベント処理サービスが必要です。応答テンプレートだけでは実際の業務処理を実行できません。
