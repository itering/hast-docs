Hast AIP は FDE の実践から生まれたプラットフォーム兼ワークベンチです。Agent の設定、システム接続、実行機能を再利用することで、プロジェクトごとに共通基盤を作り直す手間を減らし、顧客の業務フローに AI を組み込みます。

<h2 id="uses">適した導入シナリオ</h2>

企業資料の反復利用、業務ルールへの準拠、既存システムの呼び出しが必要な作業には、役割を明確にした Agent を設定できます。カスタマーサポート向けの検索と業務ツール、調査向けの資料と分析手法、運用向けの照会 API などが例です。

利用者、読み取り可能なデータ、許可する操作、結果の確認方法を事前に決めます。企業環境への導入、システム権限、本番稼働の責任は FDE と顧客で確認します。

<h2 id="capabilities">ワークベンチの機能</h2>

| 目的 | 機能 | 関連ガイド |
| --- | --- | --- |
| Agent の役割とルールを定義 | システムプロンプト、モデル、能力設定 | [Agent 管理](aip-agents) |
| 方法と資料を再利用 | Skills とナレッジベース | [Skills](aip-skills)、[ナレッジ](aip-knowledge) |
| 業務システムに接続 | HTTP ツールとシークレットのバインド | [ツール](aip-tools)、[シークレット](aip-secrets) |
| 業務の背景を引き継ぐ | メモリの読み書き範囲 | [メモリ](aip-memory) |
| 設定を検証して引き渡す | デバッグ、インポート・エクスポート、HTTP 呼び出し | [デバッグ](aip-debug)、[HTTP 接続](aip-api) |
| サーバーや外部クライアントから呼び出す | API キー、会話イベント、MCP | [API クイックスタート](aip-api-quickstart)、[MCP 連携](mcp) |

ワークベンチでは Agent の設定と接続方法を管理します。業務上の効果は実際のケースで検証してください。範囲を限定したフローから始め、出力とツール呼び出しを確認してから利用を広げます。

<h2 id="concepts">基本用語</h2>

| 用語 | 用途 |
| --- | --- |
| Agent | 保存、デバッグ、呼び出しができる設定 |
| システムプロンプト | 役割、処理ルール、出力要件 |
| Skill | 再利用可能な作業手順と付属ファイル |
| ナレッジベース | URL やファイルを索引化して検索する資料 |
| ツール | 業務 API や設定済み実行機能の利用 |
| シークレット | Agent にバインドする業務用の認証情報 |
| メモリ | 後続タスクで使う背景や好み |
| Hook | Agent の HTTP 呼び出し口。API や設定ファイル内で使う名称 |

<h2 id="workflow">設定から導入まで</h2>

1. Agent を作成し、役割とモデルを指定します。
2. 必要な資料、Skills、業務ツールを追加します。
3. 保存し、デバッグ画面で会話全体をテストします。
4. サーバーから呼び出し URL を使い、応答と停止処理を実装します。

[最初の Agent を作成](aip-quickstart)するか、既存設定を[インポート・複製](aip-config-transfer)してください。

<h2 id="state">有効状態と実行状態</h2>

Agent の有効状態は呼び出しを受け付けるかどうかを示します。有効でも、タスクの実行中や成功を意味しません。各テストの結果はデバッグ応答や呼び出しイベントで確認します。

保存後は現在の設定が使われます。変更前に[設定をエクスポート](aip-config-transfer)し、影響するフローを再テストしてください。

<h2 id="delivery">FDE と本番導入を進める</h2>

企業が業務目標とデータ利用要件を提示し、FDE が設計と導入を担当し、プラットフォームチームが共通機能を支えます。シナリオ確認、技術調査、試験運用を経て段階的に実務へ導入し、その後も問題やフィードバックを基に改善します。

[FDE の紹介](https://hast.so/ja/fde)と[プラットフォーム支援・コミュニティ](https://hast.so/ja/fde/community)をご覧ください。
