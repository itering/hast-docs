<h2 id="prepare">準備</h2>

このガイドは「WeChat → 個人 WeChat」を提供する環境向けです。すべての本番環境での提供を示すものではありません。

選択した会話をナレッジに取り込み、メッセージや既読通知は送信しません。[WeChat カスタマーサービス](aip-wechat-kf)とは別の接続方式です。新規ログインではスマートフォンの全履歴を取得できるとは限りません。

<h2 id="deploy">構築とログイン</h2>

自分のサーバーに Docker を導入し、[agent-wechat 公式インストールガイド](https://thisnick.github.io/agent-wechat/setup/install/)の Docker 手順で起動します。専用の永続ボリュームにアカウントとログイン情報を保存し、確認済みのイメージバージョンを固定してください。

[公式アカウント接続ガイド](https://thisnick.github.io/agent-wechat/setup/connect/)に従ってアカウントを作成し、QR コードをスキャンしてスマートフォンで確認します。複数アカウントには識別しやすい別名を付け、同じデータを二つのプロセスから同時に更新しないでください。

Hast バックエンドから接続先 URL に到達できる必要があります。サーバーの `localhost` はリモートの Hast からアクセスできません。自分のリバースプロキシや保護されたトンネルで HTTP または HTTPS を提供し、認証 Header の転送、イベントストリームのバッファ無効化、長時間接続を設定します。

必要なアカウントの `read` 権限に限定した専用 Token を発行します。添付ファイルが必要な場合だけ `media` を追加してください。`send`、`read-state`、管理権限は不要です。Token 発行時に管理者が使用する内部 ID を、Hast の画面に手入力する必要はありません。

<h2 id="connect">Hast に接続</h2>

1. 「チャネル → チャネル追加 → WeChat → 個人 WeChat」で既存サービスを選びます。
2. サービス URL を入力します。HTTP と HTTPS の両方を利用できます。
3. サービスの設定に合わせて Bearer Token、Basic Auth、API Key / カスタム Header を入力します。Header 名は `X-API-Key` など、ゲートウェイで設定したものを使用します。
4. アカウント取得ボタンを押します。一つなら自動選択され、複数なら選択して接続を作成します。
5. 会話を読み込み、名前や ID で検索してページごとに選択します。検索やページ移動で選択は保持されます。最後に会話範囲を保存します。

agent-wechat のネイティブ API は Bearer Token を使用します。Basic Auth や独自 API Key には、それらを検証して上流向けの認証に変換するゲートウェイが必要です。Hast の選択だけではサーバー側の設定は変わりません。

「サービスの接続設定を変更」は URL やアクセス認証情報の更新用で、WeChat のログイン画面ではありません。

<h2 id="reconnect">再ログインとデータ管理</h2>

ログアウトしたら agent-wechat の実行マシンまたは Docker コンテナに戻り、元のログインツールで再度スキャンしてスマートフォンで確認します。他の人が管理する場合は管理者に依頼してください。Hast は復旧を自動検知するため、チャネルの削除は不要です。

接続できない場合は、まずプロセス、ネットワーク、URL、認証情報を確認します。ネットワーク障害と WeChat のログアウトは同じではありません。

既存サービスの接続解除は Hast の同期のみ停止します。チャネルを削除しても外部のコンテナ、ボリューム、ログイン情報は削除しません。取り込んだナレッジや添付ファイルは既定で保持され、明示的に削除を選んだ場合だけ削除されます。バックアップや更新ではデータと認証情報を保管し、ボリューム削除コマンドに注意してください。

未処理バッチ数は上流の処理待ちを示し、同数のメッセージ消失を意味しません。イベント履歴が期限切れの場合、Hast は上流で読み取れる履歴を再取得します。上流に残っていないデータの復旧は保証できません。

<h2 id="managed-proxy">Hast ホスティングと任意のプロキシ</h2>

Hast ホスティングを選択すると、直接インスタンスを作成するか、HTTP・HTTPS・SOCKS5 プロキシを設定できます。方式、IP/ホスト名、ポート、必要に応じてユーザー名とパスワードを入力します。ホスト欄に URL スキームは不要です。

プロキシは任意です。未設定の場合はホストサーバーのネットワークと出口 IP を使います。独自の出口 IP を使う場合や WeChat に接続できない場合に設定してください。ログイン認証やアカウント制限の回避を保証するものではありません。HTTP プロキシまでの接続は暗号化されません。この接続を暗号化するには HTTPS を選択してください。

「プロキシを確認」で Hast Server が出口 IP と応答時間を確認します。設定した場合は確認成功後に作成でき、作成時にも再確認します。成功はサーバーの接続確認であり、WeChat ログイン成功の保証ではありません。送信元 IP 制限がある場合はインスタンス環境の出口 IP も許可してください。DNS と UDP はホストのネットワークを使い、現在のプロキシは IPv4 TCP を転送します。

準備完了後に QR コードを読み取り、スマートフォンで承認します。プロキシ設定は作成時に保存され、一時停止・再開後も維持されます。実行中のインスタンスのプロキシ変更には対応していません。この機能の公開により既存ログインが再起動されることはありません。初回ログイン未完了のまま期限が切れるとインスタンスを削除し、再作成時は保存済みプロキシ設定を引き継ぎます。チャネル削除時はホストされたインスタンスとプロキシ資源を削除します。同期済みナレッジは削除画面の選択に従います。

<h2 id="api-mcp">API と MCP</h2>

公開 API の接頭辞は `/api/public/v1` です。Profile API key を使用します。構成・会話一覧には `channels:read`、作成・プロキシ確認・更新・再試行・ログイン状態と QR の取得には `channels:write` が必要です。読み取り権限だけではログイン QR を取得できません。

```json
{
  "request_id": "1b42bf80-5683-4b6f-815a-5b680395ced5",
  "name": "Personal WeChat archive",
  "mode": "managed",
  "proxy": {
    "protocol": "https",
    "host": "proxy.example.com",
    "port": 8443
  }
}
```

| REST | MCP |
| --- | --- |
| `GET /channels/wechat_personal/config` | `get_channels_wechat_personal_config` |
| `POST /channels/wechat_personal/proxy/check` | `post_channels_wechat_personal_proxy_check` |
| `POST /channels/wechat_personal/probe` | `post_channels_wechat_personal_probe` |
| `POST /channels/wechat_personal` | `post_channels_wechat_personal` |
| `GET /channels/{connection_id}/wechat_personal` | `get_channels_connection_id_wechat_personal` |
| `GET /channels/{connection_id}/wechat_personal/threads` | `get_channels_connection_id_wechat_personal_threads` |
| `PATCH /channels/{connection_id}/wechat_personal` | `patch_channels_connection_id_wechat_personal` |
| `POST /channels/{connection_id}/wechat_personal/retry` | `post_channels_connection_id_wechat_personal_retry` |
| `DELETE /channels/{connection_id}` | `delete_channels_connection_id` |
| `POST /channels/{connection_id}/reconnect` | `post_channels_connection_id_reconnect` |
| `DELETE /channels/{connection_id}/remove` | `delete_channels_connection_id_remove` |

例は作成リクエストの本文です。直接接続では `proxy` を省略します。プロキシ確認には内側のプロキシオブジェクトを送信し、`exit_ip` と `latency_ms` を取得します。MCP では JSON を `body`、接続 ID を `path`、検索・ページ指定を `query` に入れます。会話一覧は `limit`（1–50）、`cursor`、`search` を受け取り、返された `nextCursor` で次ページを取得します。PATCH の `thread_ids` と `media_enabled` で取り込み対象を保存します。作成・再試行後は状態を確認し、`state=connected` になるまでログイン成功と判断しないでください。既存サービスは `mode=external`、`endpoint`、`account_id`、`credentials` を使い、先に probe でアカウントを取得します。これらの操作は WeChat メッセージを送信しません。
