<h2 id="prepare">準備</h2>

このガイドは「WeChat → 個人 WeChat」を提供する環境向けです。すべての本番環境での提供を示すものではありません。

選択した会話をナレッジに取り込み、メッセージや既読通知は送信しません。[WeChat カスタマーサービス](aip-wechat-kf)とは別の接続方式です。新規ログインではスマートフォンの全履歴を取得できるとは限りません。

<h2 id="deploy">構築とログイン</h2>

自分のサーバーに Docker を導入し、[agent-wechat 公式インストールガイド](https://thisnick.github.io/agent-wechat/setup/install/)の Docker 手順で起動します。専用の永続ボリュームにアカウントとログイン情報を保存し、確認済みのイメージバージョンを固定してください。

[公式アカウント接続ガイド](https://thisnick.github.io/agent-wechat/setup/connect/)に従ってアカウントを作成し、QR コードをスキャンしてスマートフォンで確認します。複数アカウントには識別しやすい別名を付け、同じデータを二つのプロセスから同時に更新しないでください。

Hast バックエンドから接続先 URL に到達できる必要があります。サーバーの `localhost` はリモートの Hast からアクセスできません。自分のリバースプロキシや保護されたトンネルで HTTP または HTTPS を提供し、認証 Header の転送、イベントストリームのバッファ無効化、長時間接続を設定します。

必要なアカウントの `read` 権限に限定した専用 Token を発行します。添付ファイルが必要な場合だけ `media` を追加してください。`send`、`read-state`、管理権限は不要です。Token 発行時に管理者が使用する内部 ID を、Hast の画面に手入力する必要はありません。

<h2 id="connect">Hast に接続</h2>

1. 「チャネル → チャネル追加 → WeChat → 個人 WeChat」で既存サービスを選びます。
2. サービス URL を入力します。HTTP と HTTPS の両方を利用できます。
3. サービスの設定に合わせて Bearer Token、Basic Auth、API Key / カスタム Header を入力します。Header 名は `X-API-Key` など、ゲートウェイで設定したものを使用します。
4. アカウント取得ボタンを押します。一つなら自動選択され、複数なら選択して接続を作成します。
5. 会話を読み込み、名前や ID で検索してページごとに選択します。検索やページ移動で選択は保持されます。最後に会話範囲を保存します。

agent-wechat のネイティブ API は Bearer Token を使用します。Basic Auth や独自 API Key には、それらを検証して上流向けの認証に変換するゲートウェイが必要です。Hast の選択だけではサーバー側の設定は変わりません。

「サービスの接続設定を変更」は URL やアクセス認証情報の更新用で、WeChat のログイン画面ではありません。

<h2 id="reconnect">再ログインとデータ管理</h2>

ログアウトしたら agent-wechat の実行マシンまたは Docker コンテナに戻り、元のログインツールで再度スキャンしてスマートフォンで確認します。他の人が管理する場合は管理者に依頼してください。Hast は復旧を自動検知するため、チャネルの削除は不要です。

接続できない場合は、まずプロセス、ネットワーク、URL、認証情報を確認します。ネットワーク障害と WeChat のログアウトは同じではありません。

既存サービスの接続解除は Hast の同期のみ停止します。チャネルを削除しても外部のコンテナ、ボリューム、ログイン情報は削除しません。取り込んだナレッジや添付ファイルは既定で保持され、明示的に削除を選んだ場合だけ削除されます。バックアップや更新ではデータと認証情報を保管し、ボリューム削除コマンドに注意してください。

未処理バッチ数は上流の処理待ちを示し、同数のメッセージ消失を意味しません。イベント履歴が期限切れの場合、Hast は上流で読み取れる履歴を再取得します。上流に残っていないデータの復旧は保証できません。
