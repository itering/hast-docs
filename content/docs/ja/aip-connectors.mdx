<h2 id="discover">アプリとアカウントを確認する</h2>

Connector は外部アプリのツールを認可し、メッセージチャネルを作りません。AIP Connections は同じ提供元の複数アカウントを持てます。所有者が共有するまで各アカウントは非公開です。

`connectors:read` で `/connectors/catalog?search=...&limit=20`、`/connectors/status`、`/connectors/accounts` を確認し、カーソルを最後まで取得します。返された provider slug と提供元が検証した ready 状態を使います。pending の記録だけでは利用できません。検証済み ID ラベルで区別し、不明な ID は不明と示します。所有者の表示名は提供元 ID と別です。

<h2 id="authorize">提供元の同意を完了する</h2>

`connectors:write` で `POST /connectors/{provider}/oauth/authorize` を呼び、MCP は `path.provider` を使います。対象の所有者が非公開 `auth_url` を開き、アカウントと権限を確認します。Hast API キーを提供元へ送りません。callback 後に状態とアカウントを再取得します。

拒否、保留、期限切れ、失敗は解決が必要です。クライアントが同意を開けなければ適切な非公開 UI を案内し、独立した作業を続けます。他の Profile の参照を複製したり、手動の参照を接続済みと報告しません。

`422 connector_auth_config_required` は toolkit の提供元認証設定がないことを示します。管理者に対応する認証を設定してもらってから再試行します。この失敗ではアカウントは接続されていません。

<h2 id="use">操作するアカウントを選ぶ</h2>

個人アカウント共有には所有者の同意、Workspace の承認、対象ツールを含む Organization のアプリポリシーが必要です。アプリ承認だけでは共有されません。返された選択肢を使い、ID をアクセス許可とみなしません。

人との会話 run ごとに、現在の許可で利用可能なアカウントが固定されます。ユーザーの絞り込みは会話に保持されます。`connector connected` またはネイティブ一覧で確認し、複数ある場合はローカル `connector_account_ref_id` を指定します。意図が不明ならアカウントと操作を確認し、結果の使用アカウントも調べます。

検証済みの読み取り操作は現在の許可内で自動実行できます。書き込みと未検証操作は既存のログインユーザー確認を使います。名前の接頭辞や HTTP メソッドだけでは読み取り専用と判断できません。確認は正確なアカウント、操作、引数、ツールバージョンに結び付きます。不確実な書き込みは提供元の結果を調べてから再試行します。定期実行とチャネルは別の許可に従います。

利用できる場合はネイティブ `connector` を使います。アカウント管理は Connections と管理 API で行います。カスタム HTTP ツールは明確な宛先規則と Secrets を使い、raw proxy で権限を回避しません。

<h2 id="share-tool-scope">個別ツールまたは全ツールを共有</h2>

アカウント共有時は、名前付きツールを選ぶと固定の許可になり、**すべてのツール**（`*`）を選ぶと提供元で利用できるツールが対象になります。固定リストには新しいツールは自動追加されないため、提供元のカタログが変わったら確認してください。全ツールの許可には後から追加されたツールも含まれることがあるため、広い許可が必要な場合だけ選びます。ツール共有は、アカウント所有者の同意、Organization のアプリ承認、バックグラウンド実行や外部アクセスの設定とは別です。**承認待ち**や**一部承認済み**は、すべてのアクセスが有効という意味ではありません。表示された許可と承認状態を確認してください。

<h2 id="disconnect">アカウントを更新・切断する</h2>

状態やメタデータを変更する前に `/connectors/accounts/{id}` を読みます。変更は提供元 ID の交換や同意を行いません。別の外部アカウントには新しい認可を使います。

`DELETE /connectors/accounts/{id}` は提供元との接続とローカル参照を削除します。状態と消失を確認してから成功を報告します。提供元エラーで失敗する場合があり、他のアカウントと権限は保持します。現在のフィールドは [API リファレンス](aip-api-reference)、独自サービスは[業務ツール](aip-tools)を参照してください。
