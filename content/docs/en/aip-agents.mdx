<h2 id="edit">Edit configuration</h2>

Open an Agent's detail page and choose edit. Form and JSON modes edit the same draft; changes take effect only after saving.

| Setting | Guidance |
| --- | --- |
| Name and description | Describe the business responsibility so it is easy to find and select |
| System prompt | Define inputs, processing, when to ask for more information, and output |
| Model and reasoning effort | Choose available catalog options; supported effort varies by model |
| Invocation state | Enable or disable external calls |
| Sandbox permissions | Choose according to file-writing and execution needs |
| Skills | Select the working methods needed |
| Knowledge bases | Select indexed sources |
| Policy | Enable capabilities such as retrieval or long-term memory |

Retry if resource catalogs fail to load. Refreshing preserves the draft. Adding knowledge bases enables knowledge retrieval in the form; check other capabilities separately.

If CRM or secrets are missing, use the matching “Manage in a new tab” link. Keep the Agent editor open, complete resource setup, return and refresh the CRM or secret list before selecting the new resource. Refresh reads resources without replacing the Agent name, purpose or advanced-setting draft. Closing or fully reloading the original tab can still lose unsaved content.

If you are unsure which model to choose, use Auto. See [Choose Auto](task-capabilities#auto-model) for candidates, the default, and billing behavior.

<h2 id="assistant">Use the configuration assistant</h2>

When available in your workspace, open the configuration assistant to request changes to Agents and related resources. Permission mode is set for the current conversation:

- **Wait for my approval**: important changes need your approval. Review pending changes before approving them, then check the results.
- **Full access**: this conversation can directly change, delete, and run resources you can manage. Use it only when appropriate. The assistant cannot restore a deleted resource.

Enter secret values through the secure form, not in chat. The assistant edits saved configuration, not an unsaved editor draft. After it finishes, reload the editor and reconcile any draft, then verify the result in a new debug session. For supported channel setup, the conversation may show a pairing QR code to scan and approve in the relevant app. Saved raster images may also appear inline with a download link.

<h2 id="save">Save and collaborate</h2>

Saving updates the current configuration. There is no configuration history or rollback interface; concurrent edits use the last successful save. Export a copy before important prompt or tool changes.

When leaving an unsaved editor, follow the prompt to keep editing or discard changes. After saving, verify the result in a new debug session.

<h2 id="disable">Disable and delete</h2>

Disable an Agent to stop accepting calls temporarily. Before deletion, confirm business services no longer use its URL and preserve any configuration or memory you need.

If a service synchronizes Agent configuration on startup, the next synchronization may overwrite console edits. Agree with its maintainer where changes should be made.

<h2 id="access">Manage Agent access</h2>

In the selected Workspace, open **Agent access** from the workspace management navigation. Review member and connected-source access for each Agent. Open an Agent to search, filter, and page through member, source, and historical access records. Member access follows Workspace roles: Viewers can read shared content; Editors and Admins can edit and run Agents. Manage Workspace roles in Workspace members. Stored Agent-specific read limits and revocations still apply; inspect them in the member view. Channel access is managed in the sources view: choose **Enable channel** to bind a connected channel and allow this Agent to run on it, or to restore access for a channel that is already bound. Only the Organization Owner or Admin, or the personal Workspace owner, can do this. A channel connection has one reply owner, so assigning it to another Agent revokes the previous Agent's channel and conversation access. On a channel or API-entrance record you can also enable schedule management or revoke access. Private conversations and personal connections keep their own access rules.

Conversation-specific and revoked grants appear in the history. Agents with only historical grants appear in a separate history view; their records remain available. Manage Agent definitions, schedules, and channels in the workspace workbench.
