<h2 id="prepare">Before you start</h2>

[Create and enable an Agent](aip-quickstart) in AIP. You need permission to install apps in the target Slack workspace. If approval is required, ask a workspace administrator to approve the installation. Keep AIP and the Slack App settings open.

Each Slack App has one Events Request URL. Create a separate App if an existing one serves another channel, including separate Apps for STG and production. Entering the same Bot Token in another environment does not change where events are sent. `Verified` confirms the configured URL responded correctly; also check that it belongs to the intended environment and channel. See [Slack's HTTP callback documentation](https://docs.slack.dev/apis/events-api/using-http-request-urls/).

<h2 id="automatic">Create a Slack App automatically</h2>

Add Slack from AIP Channels, choose automatic creation and enter a name. This flow does not require copying a Bot User OAuth Token or Signing Secret.

1. Open [Slack Apps](https://api.slack.com/apps), generate a temporary **Configuration Access Token** for the intended workspace, and enter it in AIP's configuration credential field.
2. Create and continue. Review the workspace and permissions on Slack's official consent page, then authorize. Wait for administrator approval when required.
3. Follow the link to App Manifest, click **Click here to verify**, and return to AIP to check status.
4. Associate an enabled Agent, then send a controlled DM or channel message and confirm the actual reply.

Continue the same setup instead of creating another App. Cancellation clears temporary credentials but does not delete an App already created. A connected state does not prove message delivery. See [automatic channel creation](aip-api-quickstart#automatic-channels) for API/MCP calls.

<Step title="Install in your workspace" id="install" stepNumber={2}>

Open `OAuth & Permissions`, add the 22 scopes below under `Bot Token Scopes`, then click `Install to Workspace`.

| Purpose | Scopes |
| --- | --- |
| Mentions and Agent | `app_mentions:read`, `assistant:write` |
| Channels and messages | `channels:history`, `channels:read`, `groups:history`, `groups:read`, `chat:write` |
| Direct messages | `im:history`, `im:read`, `im:write` |
| Group direct messages | `mpim:history`, `mpim:read`, `mpim:write` |
| Files | `files:read`, `files:write` |
| Emoji and reactions | `emoji:read`, `reactions:read`, `reactions:write` |
| Pins | `pins:read`, `pins:write` |
| Public search and users | `search:read.public`, `users:read` |

Leave `User Token Scopes` empty.

Thinking Steps uses the existing `chat:write` scope to [create and update streamed messages](https://docs.slack.dev/reference/methods/chat.startStream/) and [delete the Bot's own temporary steps message](https://docs.slack.dev/reference/methods/chat.delete/) after completion. No additional scope or event subscription is needed; the complete JSON already includes the required permissions. If an older App lacks a scope, add it, reinstall the App in the workspace, and update its Bot Token in AIP.

<Note>

<h2 id="reply-rules">Configure reply triggers</h2>

In Slack reply trigger settings, configure channels or senders that do not need a mention. Use Channel IDs for channels and Slack User IDs or Bot IDs for senders. Separate multiple IDs with newlines or commas.

In channels the Bot has joined, any mention, channel exception, or sender exception can trigger a reply. For automated alerts, enter the alert Bot's ID. The Bot ignores its own messages.

To find a Channel ID, click the channel name in Slack, open `About`, and copy `Channel ID` at the bottom.

<h2 id="operation-progress">Show operation progress</h2>

Turn "Show detailed operation progress" on or off in channel settings. Each channel saves its own setting, enabled by default. Thinking Steps shows actual tool operations and public progress text the Agent emits. It does not display raw reasoning or generate extra narration. The temporary steps message is deleted after the final reply is delivered.

When disabled, subsequent requests retain only the final reply and any plan the Agent actually produces. If the Token lacks streaming permission or its type is unsupported, Thinking Steps is skipped and an ordinary reply is still sent. An invalid Token requires reconnecting the channel. Rate limits and temporary failures are retried, not treated as missing permissions.

<h2 id="troubleshooting">Troubleshooting</h2>

<AccordionGroup>

<Accordion title="Request URL verification fails">

Check that Socket Mode is off, the full callback belongs to the current channel, and the Signing Secret comes from the same Slack App. The callback must be publicly reachable over HTTPS. Correct the settings, select `Retry`, and save after `Verified` appears.

</Accordion>

<Accordion title="Verified, but no reply">

Check channel membership, all five event subscriptions, reinstallation after scope changes, the enabled Agent assigned in AIP, and the current reply triggers. Start by mentioning the Bot in a channel or sending it a direct message.

If it still does not reply, give an administrator the channel name and send time. For attachment failures, also check `files:read`, `files:write`, and the Agent's file access and capabilities.

</Accordion>

<Accordion title="An older channel stopped receiving messages">

Check whether the same Slack App was reused and its Events Request URL replaced. Restore the old callback and create a separate App for the new channel.

</Accordion>

<Accordion title="Chat works, but search or history does not">

For history, provide a Channel ID for a channel the Bot has joined. For thread replies, also provide the Thread ID. Slack permissions apply to both public and private channels.

Public search uses `search:read.public` and may include public channels the Bot has not joined. It does not provide global private-channel search. Check that the installed Token has the scope and administrator approval. See [Slack's public search scope](https://docs.slack.dev/reference/scopes/search.read.public/).

</Accordion>

</AccordionGroup>
