<h2 id="create">Create a schedule</h2>

In a view-only workspace, you can inspect schedules but cannot create, edit, pause, resume, or delete them.

1. Open scheduled tasks and create a new one.
2. Write complete instructions for every run, rather than “repeat the last task.”
3. Choose hourly, daily, weekdays, or weekly and set the time.
4. Check timezone, model, and reasoning effort in advanced settings.
5. Save and verify Next run in the list.

```text
Summarize new issues in the specified project from the past day.
Create an English brief with issue title, link, and current status.
If there are none, state “No new issues in the past day.”
```

Authorize required external apps in Connectors first and name the project explicitly.

<h2 id="cron">Custom Cron</h2>

Advanced settings support five-field Cron. This runs every Monday at 09:00 in the selected timezone:

```text
0 9 * * 1
```

Use a timezone name such as `Asia/Shanghai`. Check Next run after saving; do not confuse the browser's local time with the schedule's timezone.

<h2 id="runs">Inspect results</h2>

Select a schedule and view status and output in recent runs. Open the associated task or files. To compare runs across Agents, open the [Agent run report](aip-debug#run-report). Run history is read-only; edit the schedule's instructions to change future executions.

<h2 id="saved-assignment">Follow up on a saved Team Task</h2>

Saving a Team Task records its lead, members, permitted capabilities, and defaults. Later Team edits apply to new assignments. To use an updated Team for future runs of this Task, edit its assignment and save it again.

In Task history, open the completed run you want. Its result stays available even after a newer run finishes. Select **Open original conversation** to continue a Team discussion, or **Ask Assistant** when that action is available for an individual run. To ask about an earlier result in your current chat, identify the Task and the run. Use **Run once** to start a separate execution.

For a Task that groups events by topic, a new webhook event can continue the original work. Only Agents assigned to both the original work and the current Task can see the new input. A retry of the same event reuses its receipt. Private instructions and selected knowledge keep their existing access.

<h2 id="pause">Pause, resume, and delete</h2>

Pausing stops future automatic scheduling. Check Next run after resuming. Deleting a schedule prevents later automatic runs; confirm the selected task first.

An enabled schedule does not guarantee a successful run. On failure, inspect history, model availability, authorization, and inputs.

<h2 id="preconditions">Optional Python preconditions</h2>

A timed Task can run a read-only Python check before it starts the Agent. The script reads the schedule ID, run time, and trigger as JSON from standard input. End the output with a JSON decision.

- `{"run":true}` starts the Agent. Include `context` to pass data into the run.
- `{"run":false,"reason":"No changes"}` skips the Agent and records the reason in the run history.
- A script error, timeout, or invalid decision records a failed run. Open its diagnostic, correct the script or inputs, and use **Run once** to check the fix.
