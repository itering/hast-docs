<h2 id="prepare">Before you start</h2>

This guide applies to deployments offering WeChat → Personal WeChat. Availability depends on your environment; the guide does not announce availability in every production deployment.

Personal WeChat imports selected chats into Knowledge without sending messages or read receipts. It is separate from [WeChat Customer Service](aip-wechat-kf). A new login may not provide the complete history stored on your phone.

<h2 id="deploy">Deploy and sign in</h2>

Install Docker on your own server and start the service using the Docker instructions in the [official agent-wechat installation guide](https://thisnick.github.io/agent-wechat/setup/install/). Keep account data and sessions in a dedicated persistent volume, and pin a verified image version.

Follow [Connect your account](https://thisnick.github.io/agent-wechat/setup/connect/) to create an account, scan its QR code, and confirm on your phone. Give multiple accounts recognizable aliases. Never run two writers against the same account data.

The Hast backend must reach the service URL. Your server's `localhost` cannot be reached as localhost by a remote Hast deployment. Use your own reverse proxy or protected tunnel for HTTP or HTTPS access. Forward authentication headers, disable event-stream buffering, and allow long connections.

Issue a dedicated token scoped to the required account with `read`, adding `media` only for attachment downloads. Do not grant `send`, `read-state`, or administrative scopes. The service administrator may need an account ID when issuing the token; Hast lists accessible accounts automatically.

<h2 id="connect">Connect Hast</h2>

1. Open Channels → Add channel → WeChat → Personal WeChat, then select Existing service.
2. Enter the service URL. Both HTTP and HTTPS are supported.
3. Enter the authentication required by your service: Bearer Token, Basic Auth, or API Key / custom headers. `X-API-Key` is one possible header name; use the name configured on your gateway.
4. Select Load WeChat accounts. A single account is selected automatically; choose one when multiple accounts are available, then create the connection.
5. Load chats, search by name or ID, browse pages, and select chats. Selections survive pagination and searches. Save the chat selection when finished.

The native agent-wechat API uses Bearer tokens. Basic Auth and custom API keys require a gateway that validates them and forwards authentication accepted by the upstream service. Choosing an option in Hast does not configure that gateway.

Edit service connection settings changes the URL or access credentials. It is not the WeChat sign-in screen.

<h2 id="reconnect">Reconnect and manage data</h2>

If WeChat signs out, return to the machine or Docker container running agent-wechat. Use its original login tool to scan again and confirm on your phone. Contact its administrator if someone else maintains it. Hast detects recovery automatically; do not delete the channel.

If the service is unreachable, check its process, network, URL, and credentials first. A network failure does not necessarily mean WeChat signed out.

For Existing service connections, disconnecting stops Hast synchronization. Deleting the channel does not delete your external container, volume, or login. Imported Knowledge and attachments are retained by default; they are removed only when explicitly requested. Preserve the volume and credentials during backups and upgrades, and avoid commands that remove volumes unintentionally.

Pending batches indicate unfinished upstream processing, not an equivalent count of lost chat messages. When event history expires, Hast backfills history still readable upstream. Data no longer retained upstream cannot be guaranteed recoverable.

<h2 id="managed-proxy">Hast hosting and optional proxy</h2>

Choose Hast hosting to create an instance directly, or configure your HTTP, HTTPS or SOCKS5 proxy first: protocol, IP/hostname, port, and optional username/password. Enter the host without a URL scheme.

A proxy is optional. Without one, WeChat uses the hosted server's network and outbound IP. Use a proxy to select your own outbound IP or when the hosted network cannot reach WeChat. A proxy does not guarantee avoiding login verification or account restrictions. An HTTP proxy connection is not encrypted; choose HTTPS to encrypt the connection to the proxy.

Check proxy queries the outbound IP from Hast Server and shows latency. A configured proxy must pass before creation; the server checks again when creating. Success confirms server connectivity, not WeChat login. If the proxy uses source-IP allowlists, allow the instance environment's outbound IP too. DNS and UDP retain hosted networking; the current proxy forwards IPv4 TCP connections.

Scan the QR code after preparation and approve on your phone. Proxy settings are saved at creation and retained across pause/resume. Changing a running instance's proxy is not supported; this feature does not restart existing logins. An instance that never completes first login is removed after its setup deadline; recreation retains the saved proxy settings. Deleting the channel cleans up hosted instance and proxy resources; indexed knowledge follows your deletion selection.

<h2 id="api-mcp">API and MCP</h2>

Public API prefix: `/api/public/v1`. Use a Profile API key. Configuration and conversation listing require `channels:read`; creation, proxy checks, updates, retries and login-status/QR reads require `channels:write`. Read-only access does not expose login QR codes.

```json
{
  "request_id": "1b42bf80-5683-4b6f-815a-5b680395ced5",
  "name": "Personal WeChat archive",
  "mode": "managed",
  "proxy": {
    "protocol": "https",
    "host": "proxy.example.com",
    "port": 8443
  }
}
```

| REST | MCP |
| --- | --- |
| `GET /channels/wechat_personal/config` | `get_channels_wechat_personal_config` |
| `POST /channels/wechat_personal/proxy/check` | `post_channels_wechat_personal_proxy_check` |
| `POST /channels/wechat_personal/probe` | `post_channels_wechat_personal_probe` |
| `POST /channels/wechat_personal` | `post_channels_wechat_personal` |
| `GET /channels/{connection_id}/wechat_personal` | `get_channels_connection_id_wechat_personal` |
| `GET /channels/{connection_id}/wechat_personal/threads` | `get_channels_connection_id_wechat_personal_threads` |
| `PATCH /channels/{connection_id}/wechat_personal` | `patch_channels_connection_id_wechat_personal` |
| `POST /channels/{connection_id}/wechat_personal/retry` | `post_channels_connection_id_wechat_personal_retry` |
| `DELETE /channels/{connection_id}` | `delete_channels_connection_id` |
| `POST /channels/{connection_id}/reconnect` | `post_channels_connection_id_reconnect` |
| `DELETE /channels/{connection_id}/remove` | `delete_channels_connection_id_remove` |

The example is the create request body. Omit `proxy` for direct egress. Proxy check accepts the inner proxy object and returns `exit_ip` and `latency_ms`. For MCP, put request JSON under `body`, the connection ID under `path`, and pagination/search under `query`. Conversation listing accepts `limit` (1–50), `cursor`, and `search`; use the returned `nextCursor`. PATCH `thread_ids` and `media_enabled` to select ingestion. Poll status after creation or retry; never claim successful login before `state=connected`. Existing-service setup uses `mode=external`, `endpoint`, `account_id`, and `credentials`; probe first. These operations do not send WeChat messages.
