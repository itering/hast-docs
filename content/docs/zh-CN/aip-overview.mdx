Hast AIP 是团队在 FDE 实践中沉淀的平台与工作台。它为交付团队提供可复用的 Agent 配置、系统连接和运行能力，帮助团队把客户的业务流程接入 AI，减少不同项目之间重复搭建基础能力的工作。

<h2 id="uses">适合哪些交付场景</h2>

当一项工作需要反复使用企业资料、遵循业务规则，或调用已有系统时，可以先在 AIP 中配置一个职责明确的 Agent。例如，为客服流程准备知识检索与业务工具，为研究工作配置资料和分析方法，或将运维流程中的查询接口交给 Agent 调用。

开始前应确定谁使用 Agent、它能读取什么、允许执行哪些动作，以及怎样检查结果。涉及企业部署、系统权限和上线责任时，由 FDE 与客户共同确认项目方案。

<h2 id="capabilities">工作台提供什么</h2>

| 工作需要 | 对应能力 | 继续阅读 |
| --- | --- | --- |
| 明确 Agent 的职责和处理规则 | 系统提示词、模型与能力配置 | [管理 Agent](aip-agents) |
| 复用团队的方法和资料 | Skills 与知识库 | [管理 Skills](aip-skills)、[添加知识库](aip-knowledge) |
| 接入业务系统 | HTTP 工具与机密绑定 | [连接业务工具](aip-tools)、[管理机密](aip-secrets) |
| 延续业务背景 | 设置记忆的读取与写入范围 | [长期记忆](aip-memory) |
| 检查并交付配置 | 调试对话、导入导出与 HTTP 调用 | [调试 Agent](aip-debug)、[HTTP 接入](aip-api) |
| 从服务端或外部客户端调用 | API 密钥、会话事件与 MCP | [API 入门](aip-api-quickstart)、[MCP 接入](mcp) |

工作台用于维护 Agent 的配置和接入方式；业务效果需要用实际案例验证。先选一个范围清楚的流程，检查输出和工具调用，再决定是否扩大使用范围。

<h2 id="concepts">先认识几个概念</h2>

| 名称 | 用途 |
| --- | --- |
| Agent | 一份可保存、调试和调用的配置 |
| 系统提示词 | 说明 Agent 的职责、处理规则和输出要求 |
| Skill | 保存可复用的工作方法及附属文件 |
| 知识库 | 索引网址或文件，供 Agent 检索资料 |
| 工具 | 让 Agent 请求业务接口或使用配置的运行能力 |
| 机密 | 保存业务凭证，并在 Agent 配置中绑定使用 |
| 记忆 | 保存后续任务还需要读取的背景和偏好 |
| Hook | Agent 的 HTTP 调用入口；接口和配置文件中使用这个名称 |

<h2 id="workflow">配置与交付流程</h2>

1. 创建 Agent，写清职责并选择模型。
2. 按任务需要添加资料、技能或业务工具。
3. 保存配置，到调试页测试一次完整对话。
4. 在服务端使用调用地址，处理回复和停止操作。

从 [创建第一个 Agent](aip-quickstart) 开始。已有配置可以 [导入或复制](aip-config-transfer)。

<h2 id="state">启用状态与运行状态</h2>

Agent 的启用状态决定它是否接受调用。显示“启用”不代表某次任务正在运行，也不代表一次调用已成功完成。一次测试的结果需要在调试回复或调用事件中查看。

Agent 保存后使用当前配置。修改时建议先 [导出配置](aip-config-transfer) 留存，再调试受影响的流程。

<h2 id="delivery">与 FDE 一起推进上线</h2>

企业提供业务目标和数据使用要求，FDE 负责方案与交付，平台团队支持共性的基础能力。项目从场景确认、技术发现和试点验证开始，再分阶段进入实际业务；上线后结合运行问题和用户反馈继续改进。

合作流程见 [FDE 介绍](https://hast.so/zh-CN/fde)，平台支持与团队协作方式见 [FDE 能力与社区](https://hast.so/zh-CN/fde/community)。
