<h2 id="create">创建时间表</h2>

在只读工作区中，你可以查看时间表，但不能创建、编辑、暂停、恢复或删除时间表。

1. 打开“定时任务”，选择“新建定时任务”。
2. 填写每次执行的完整要求，不要只写“重复上次任务”。
3. 选择每小时、每天、每个工作日或每周，并设置时间。
4. 在高级设置中核对时区、模型和推理等级。
5. 保存后检查列表中的“下次运行”。

```text
整理指定项目过去一天的新问题。
按问题标题、链接、当前状态生成中文简报。
如果没有新问题，明确写“过去一天没有新问题”。
```

如果任务依赖外部应用，先在连接器中完成授权，并在要求中写出具体项目。

<h2 id="cron">自定义 Cron</h2>

高级设置支持五段 Cron。以下示例表示所选时区的每周一 09:00：

```text
0 9 * * 1
```

时区可填写 `Asia/Shanghai` 等名称。保存后再检查下次运行时间，避免把浏览器当地时间与任务时区混淆。

<h2 id="runs">查看运行结果</h2>

选中一个定时任务，在“最近运行”查看状态和输出。可以打开对应任务或文件。要比较不同 Agent 的运行情况，请查看 [Agent 运行报告](aip-debug#run-report)。定时任务的运行记录是只读查看入口，需要调整下一次执行时修改时间表中的任务要求。

<h2 id="saved-assignment">追问已保存的团队任务</h2>

保存团队任务时会记录负责人、成员、权限范围和默认设置。之后对团队的修改会用于新分配的任务。现有任务若要在后续运行中使用更新后的团队，需编辑该任务的团队分配并重新保存。

在任务历史中打开要核对的那次已完成运行。即使后来又运行过，这里也会保留所选那一次的结果。团队任务可以选择**打开原对话**继续讨论；单个 Agent 的运行如显示**问 Assistant**，可从这里追问。在当前对话里询问旧结果时，请指明任务和具体哪次运行。需要重新执行时，选择**运行一次**。

如果任务按话题归集事件，新的 Webhook 事件可以接着原来的工作处理。只有同时参与原始工作、且仍在当前任务分配中的 Agent 能看到这条新输入。同一事件重试会复用原回执。私密指令和已选择的知识仍按原有权限访问。

<h2 id="pause">暂停、恢复和删除</h2>

暂停会停止后续自动调度，恢复后重新查看下次运行时间。删除时间表会停止之后的自动运行；操作前确认选择的是正确任务。

时间表启用与某次运行成功是两件事。执行失败时查看运行记录，检查模型、授权和输入资料。

<h2 id="preconditions">可选 Python 前置条件</h2>

定时任务可以在启动 Agent 前执行只读 Python 检查。脚本从标准输入读取包含时间表 ID、运行时间和触发来源的 JSON，最后一行输出 JSON 决定是否运行。

- `{"run":true}` 启动 Agent。可用 `context` 向这次运行传入数据。
- `{"run":false,"reason":"No changes"}` 跳过 Agent，并在运行历史中记录原因。
- 脚本异常、超时或输出无效时，这次运行标记为失败。在历史中打开诊断信息，修正脚本或输入，再用**运行一次**验证。
