<h2 id="discover">发现应用和账号</h2>

Connector 授权外部应用工具，不会创建消息渠道。AIP Connections 可以连接同一提供方的多个账号，每个账号在所有者共享前保持私有。

使用 `connectors:read` 查询 `/connectors/catalog?search=...&limit=20`、`/connectors/status` 和 `/connectors/accounts`，跟随目录游标，使用准确的 provider slug。以提供方验证的 ready 状态为准，pending 本地记录不能视为可用连接。账号用已验证身份标签区分；身份不可用应明确显示。所有者填写的名称与提供方身份不同。

<h2 id="authorize">完成提供方授权</h2>

使用 `connectors:write` 调用 `POST /connectors/{provider}/oauth/authorize`，MCP 参数使用 `path.provider`。由目标所有者打开私有 `auth_url`，确认账号和应用权限，不向提供方发送 Hast API 密钥。回调后重新读取状态和账号。

拒绝、待授权、过期或失败需要处理。客户端不能打开授权时，提供适当的私有 UI 流程并继续其他独立工作。不复制其他 Profile 的账号，也不把手工填写的账号引用报告为已连接。

`422 connector_auth_config_required` 表示 toolkit 缺少提供方认证配置。请管理员为该 toolkit 配置支持的认证方式，再重试；失败请求没有连接账号。

<h2 id="use">为每个动作选择账号</h2>

共享个人账号需要所有者同意、Workspace 批准和覆盖选定工具的 Organization 应用策略。应用批准本身不会共享任何账号。使用返回的共享与账号选项，资源 ID 不等于访问授权。

每次人类对话 run 按当前授权固定可用账号，用户缩小的选择会保留在会话中。通过 `connector connected` 或原生账号列表确认账号；存在多个账号时提供本地 `connector_account_ref_id`。账号或动作有歧义时先确认，再检查结果中报告的实际账号身份。

平台可在当前授权范围内自动执行已验证只读动作。写入及未验证动作使用已有的登录用户审核流程。工具名前缀或 HTTP 方法不能单独证明只读。审核绑定具体账号、操作、参数和工具版本。写入结果不确定时先检查提供方结果，再考虑重试。调度和渠道 run 使用各自的授权。

优先使用原生 `connector` 工具。外部账号管理通过 Connections 和管理 API 完成。自定义 HTTP 工具使用明确的目标规则和 Secrets；raw proxy 不能绕过账号和工具授权。

<h2 id="share-tool-scope">选择固定工具或全部工具</h2>

共享账号时，选择具体工具会创建固定授权；选择**全部工具**（`*`）则覆盖提供方当前可用工具。固定列表不会自动加入新工具；提供方目录更新后应重新检查。全部工具授权可能包含以后新增的工具，仅在确实需要更广权限时使用。工具共享与账号所有者同意、Organization 应用批准，以及后台或外部访问选项彼此独立。显示**等待批准**或**部分批准**时，并不代表全部访问已生效。请先核对页面显示的授权范围和批准状态。

<h2 id="disconnect">维护或断开账号</h2>

修改支持的状态或元数据前，读取 `/connectors/accounts/{id}`。这类更新不能替换提供方身份或建立授权；要连接其他外部账号，应重新完成授权。

`DELETE /connectors/accounts/{id}` 断开提供方账号并移除本地引用，回读账号与状态后再报告成功。提供方错误可能阻止操作，应保留其他账号及其授权。当前字段见 [API 参考](aip-api-reference)，自定义服务见[业务工具](aip-tools)。
