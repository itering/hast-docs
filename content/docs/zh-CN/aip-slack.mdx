<h2 id="prepare">开始前</h2>

准备一个[已启用的 Agent](aip-quickstart)，以及 Slack 工作区的 App 安装权限。

<Note>
如果 Slack App 由你自行管理，每个 App 只能配置一个 Events Request URL。独立路由的频道以及 STG/生产应使用不同 App，避免覆盖已有渠道的[消息回调](https://docs.slack.dev/apis/events-api/using-http-request-urls/)；在另一个环境复用同一 Bot Token 不会改变事件接收地址。`Verified` 只表示当前 URL 验证成功，还需核对它属于目标环境和频道。
</Note>

<h2 id="shared-app">使用共享 HAST Slack App（如有）</h2>

如果 AIP 为当前 Agent 提供共享 HAST Slack App，可在每个 Slack 工作区安装一次；同一工作区的其他 Agent 可以复用该安装。为每个 Agent 设置独立的 `@handle` 并选择允许它回复的频道。handle 在工作区内必须唯一，并使用小写字母、数字、连字符或下划线。多个 Agent 可以共用一个频道：提及目标 Agent 的 `@handle` 即可将消息路由到它，回复会留在该 Agent 的线程中。每个 Agent 的独立 handle 需要 Slack 套餐支持用户组；如果当前套餐不支持，请改用独立 Bot。私有频道需先在 Slack 的“频道详情”→“集成”→“添加应用”中添加 HAST。

<Note>
保存配置不代表消息已送达。在已选择的频道中提及该 Agent 的 `@handle` 并确认实际回复。如果当前环境没有共享 App 选项，请按下方自动创建或自主管理 App 的步骤操作。
</Note>

<h2 id="automatic">自动创建 Slack App</h2>

在 AIP「渠道」中添加 Slack，选择自动创建并填写名称。此方式不需要手动复制 Bot User OAuth Token 或 Signing Secret。

1. 打开 [Slack Apps 后台](https://api.slack.com/apps)，为目标工作区生成临时 **Configuration Access Token**，填入 AIP 的配置凭据字段。
2. 创建并继续，在 Slack 官方授权页核对工作区和权限后授权；如需管理员批准，等待批准后继续。
3. 按页面提示进入 App Manifest，点击 **Click here to verify**，再回到 AIP 检查状态。
4. 渠道就绪后关联已启用的 Agent；在私信或已加入的频道中发送测试消息，确认收到实际回复。

保留同一次配置继续操作。取消会清除临时凭据，但不会删除已创建的 Slack App。连接成功不代表消息已经送达。API／MCP 调用见 [自动创建渠道](aip-api-quickstart#automatic-channels)。

<Step title="安装到工作区" id="install" stepNumber={2}>

进入 `OAuth & Permissions`，在 `Bot Token Scopes` 中添加下表的 23 项权限，再点击 `Install to Workspace`。

| 用途 | 权限 |
| --- | --- |
| 提及与 Agent | `app_mentions:read`, `assistant:write` |
| 频道与消息 | `channels:history`, `channels:read`, `groups:history`, `groups:read`, `chat:write` |
| 消息头像 | `chat:write.customize` |
| 私聊 | `im:history`, `im:read`, `im:write` |
| 多人私聊 | `mpim:history`, `mpim:read`, `mpim:write` |
| 附件 | `files:read`, `files:write` |
| 表情与回应 | `emoji:read`, `reactions:read`, `reactions:write` |
| 置顶 | `pins:read`, `pins:write` |
| 公开搜索与用户 | `search:read.public`, `users:read` |

`User Token Scopes` 留空。

`chat:write.customize` 允许 Hast 为消息设置生成头像。独立 Bot 已有自定义 Slack 头像时保留原头像，仅使用默认图标的 Bot 才补充生成头像；共享 App 的不同 Agent 使用各自的头像。已有 App 需在 `Bot Token Scopes` 补充此权限，并重新安装到工作区；若 Slack 签发了新 Bot Token，再到 AIP 更新。

对于按此清单配置的自建 App，Thinking Steps 使用已有的 `chat:write` 权限来[创建和更新流式消息](https://docs.slack.dev/reference/methods/chat.startStream/)，完成后用同一权限[删除 Bot 自己的临时步骤消息](https://docs.slack.dev/reference/methods/chat.delete/)。无需新增 scope 或事件订阅；完整 JSON 已包含所需权限。较早的自建 App 若缺少权限，补齐后重新安装到工作区，并在 AIP 更新该 App 的 Bot Token。

<Note>
在 `Bot Token Scopes` 中核对上表 23 项权限，`User Token Scopes` 留空。修改后需重新安装；若工作区要求审批，先提交申请。 下方截图为旧版权限列表，还需补充 `chat:write.customize`。

<h2 id="reply-rules">设置回复触发规则</h2>

在“Slack 回复触发规则”中设置免 @ 回复：

| 设置 | 填写内容 |
| --- | --- |
| 无需 @智能体的频道 | Channel ID |
| 无需 @智能体的发送者 | Slack User ID 或 Bot ID |

多个 ID 用换行或逗号分隔。

Bot 加入频道后，@Bot 或匹配任一免 @ 规则即可触发回复。自动告警可填写告警机器人的 ID；Bot 会忽略自己的消息。

查找 Channel ID：点击 Slack 频道名称 → `About`，复制底部的 `Channel ID`。

<h2 id="operation-progress">显示操作进度</h2>

如果当前渠道提供“处理状态展示”设置，可分别控制状态表情、详细操作进度（包括工作状态）和生成中的回复预览；这些展示项默认开启。“静默模式”会同时关闭三项，但最终回复和转发消息仍会送达。各项可以单独调整，平台仅展示自身支持的反馈。

如果 Slack 回复触发规则中提供“显示详细操作进度”，该设置会控制操作预览、计划卡片和工作状态。设置按频道分别保存，默认开启。开启后，Thinking Steps 会展示真实工具操作及 Agent 输出的公开进展文字，不展示原始 reasoning，也不会额外生成说明。最终回复发送后，AIP 会删除临时步骤消息。关闭后，操作预览、计划卡片和工作状态会隐藏，但最终回复仍会发送。

如果 Token 缺少流式权限或类型不受支持，系统跳过 Thinking Steps，继续发送普通回复。Token 失效需重新连接渠道；限流和临时故障会重试，不能当作缺少权限处理。

<h2 id="troubleshooting">常见问题</h2>

<AccordionGroup>

<Accordion title="Request URL 无法验证">

确认 Socket Mode 已关闭，回调 URL 完整且属于当前渠道，Signing Secret 来自同一个 Slack App。回调必须能从公网通过 HTTPS 访问。修正后在 Slack 点击 `Retry`，等待 `Verified` 后保存。

</Accordion>

<Accordion title="已经 Verified，仍没有回复">

依次检查 Bot 是否加入频道、五类事件是否保存、修改权限后是否重新安装、AIP 是否关联已启用的 Agent，以及消息是否满足回复触发规则。测试时先在频道中 @Bot，或直接私聊。

仍无回复时，将渠道名称和发送时间交给管理员排查。附件失败时，还需核对 `files:read`、`files:write` 以及 Agent 的文件操作和可用能力设置。

</Accordion>

<Accordion title="新渠道接入后，旧渠道收不到消息">

如果使用自己管理的 App，检查其 Events Request URL 是否被替换。恢复旧回调，并为新频道使用另一个 App。如果使用共享 HAST Slack App，检查目标 Agent 的设置是否仍选择了旧频道，再在旧频道中提及目标 Agent 的 `@handle` 并确认实际回复。

</Accordion>

<Accordion title="能聊天，但无法搜索或读取历史">

读取历史时，向 Agent 提供 Bot 已加入频道的 Channel ID；读取线程时再提供 Thread ID。公共和私有频道都受 Slack 授权限制。

公开搜索使用 `search:read.public`，可能包含 Bot 尚未加入的公开频道，不提供私有频道全局搜索。检查当前安装的 Token 是否已获得该权限和管理员批准。范围说明见 [Slack 公开搜索权限](https://docs.slack.dev/reference/scopes/search.read.public/)。

</Accordion>

</AccordionGroup>
