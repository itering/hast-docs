<h2 id="choose">选择渠道流程</h2>

消息渠道和 Connector 账号用途不同。修改前读取 `/channels/setup`、`/channels`、`/channels/agents` 和目标 Agent，使用具有 `channels:read/write` 的 Profile API 密钥。

新建 Slack App 或 Telegram Bot 可按[自动渠道配置](aip-api-quickstart#automatic-channels)操作。重试复用相同 setup ID 和请求 UUID。提供方同意、Slack URL 验证和最后的 `/complete` 是独立步骤；取消 setup 不会删除已创建的外部应用。

已有凭证时，用 `POST /channels/setup` 和目录返回的提供方字段。网站使用 `website_url`；Slack 的 bot token 与 signing secret 必须来自同一个 App；Telegram 使用对应 bot token。Email、LINE、SMS、Twilio 使用文档规定的字段。已有 inbox 时先查 `/channels/inboxes`，避免重复创建。

手动 WhatsApp Cloud API 见[专门指南](aip-whatsapp-api)。WhatsApp Web 仅用于归档，不能触发 Agent、回复或接收调度发送。QR 配对需要 `channels:write`，重试保留同一个 connection ID，并由实际账号所有者扫码。个人微信同样提供只读 Knowledge 来源，不是自动回复渠道。

<h2 id="install">完成提供方安装</h2>

读取 `/channels/{connection_id}/installation`，使用返回的准确 callback URL、验证 token、widget script 或转发地址。创建连接不代表已安装或授权。凭证、私有授权链接和配对 QR 不进入公开交付说明。

企业微信客服先用 `corp_id`、`callback_token`、`encoding_aes_key` 创建草稿。按安装信息配置回调、域名和可信 IP，再以 `corp_secret` 调用 `POST /channels/{connection_id}/wechat-kf/accounts`。按名称选择 `manage_privilege: true` 的账号，再 PATCH 同一渠道，提交该 Secret 和 `open_kfid`。发现账号不会自动保存凭证或绑定。见[微信客服](aip-wechat-kf)与 [MCP 示例](mcp#wechat-accounts)。

OAuth 提供方需要所有者打开返回链接并完成同一次授权，再回读连接。明确说明拒绝、待授权或配置不可用，避免创建重复连接。

<h2 id="bind">绑定 Agent 并选择行为</h2>

读取 `/webhooks/{hook_id}/channels`，再 PUT 完整目标 `connection_ids`，保留仍需要的现有连接。一个渠道只能有一个回复 Agent；遇到 `409`，先检查当前关联。该绑定同时开启触发和回复，Knowledge collection 授权独立配置。旧 `/channels/{connection_id}/binding` 仅释放关联，不能分配新 Agent。

WhatsApp、微信客服和 Telegram 默认使用准入规则，开放客服前应明确选择。成员和管理员属于具体渠道，Slack 使用其自身的参与模型。

替换 Slack 触发规则前读取安装状态。`require_mention` 与发送者、渠道例外列表共同生效。空数组会清除例外，两个数组各最多 100 个唯一 ID。自身 bot 消息不触发，修改时保留仍需要的例外。

新增关联会在保存绑定前协调执行授权。重新保存未变化的列表，不会恢复已撤销的授权。
绑定写入需要 `channel-credentials:write` 和密钥创建者匹配的当前登录会话。
获授权用户可在同一 PUT 路径明确提交
`{"enable_connection_ids":["OWNED_CONNECTED_CHANNEL"]}`，恢复指定来源并保留其他选择。
如果执行时报告 Workspace 权限不足，应按[客户端指南](aip-agent-client#identity)
检查 Agent 访问概览和来源授权。管理修复由获授权用户完成，托管 Assistant 不得自行提权。

<h2 id="verify">验证消息与反馈</h2>

回读 Agent 关联和安装状态。用已授权消息验证入站、Agent 完成、原会话中的回复及送达记录。提供方接收请求不等于最终送达。

`GET/PATCH /channels/{connection_id}/presentation` 控制 `show_status_reactions`、`show_tool_progress` 和 `streaming_replies`。默认均为 true，省略字段保留原值。全部设为 false 只隐藏进度反馈，不改变消息接收、触发或最终回复；最终回复由 Agent 回复策略决定。

归档消息、Agent 触发、知识授权和主动发送是不同能力。附件读取或下载使用返回的元数据，不自行拼接地址。断开或重连前确认影响：暂停接收后，保留的 Knowledge 仍可能存在。
