<h2 id="choose">选择工具类型</h2>

| 配置 | 适用情况 |
| --- | --- |
| HTTP 动态工具 | 把一个有明确名称、参数和结果的业务操作提供给 Agent |
| 事件工具 | 向已有事件处理集成发出工具事件，并配置响应模板 |
| HTTP 代理 | 配置允许访问的主机和需要注入的请求头 |

<h2 id="http">配置 HTTP 动态工具</h2>

以查询订单为例，你需要先准备一个可以接收请求并返回 JSON 的业务接口。

1. 在 Agent 编辑页打开业务工具窗口，添加 HTTP 工具。
2. 名称填写 `lookup_order`，说明填写“根据订单号查询当前状态”。
3. 填写业务服务的 HTTP 地址。
4. 添加输入 Schema，声明 `order_id` 为必填字符串。
5. 如需认证，在请求头使用已绑定的机密引用。
6. 应用工具配置，再保存 Agent。

```json
{
  "type": "object",
  "properties": {
    "order_id": {"type": "string", "description": "客户提供的订单号"}
  },
  "required": ["order_id"],
  "additionalProperties": false
}
```

调试时发送“查询订单 DEMO-001 的状态”。检查是否调用了正确工具、参数是否完整、返回内容是否足以回答问题。示例订单号需要替换为你的测试数据。

<h2 id="proxy">配置 HTTP 代理</h2>

按业务需要填写主机规则和请求头。凭证使用机密引用，不在提示词里粘贴真实令牌。保存前核对主机范围，避免把一个业务系统的认证头发送到其他目标。

<h2 id="troubleshoot">调用失败时检查</h2>

先看调试中的工具错误，再检查接口地址、输入 Schema、请求头和机密绑定。工具窗口的“应用”只更新草稿，退出窗口后还需要保存 Agent。

事件工具需要配套的业务事件处理服务。只填写响应模板不能代替实际的业务处理。
